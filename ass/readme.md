# ASS — Aufbau Style Sheets

ASS is a browser-first style sheet language and execution engine built on top of the `@cosmonaut` toolchain (`@cosmonaut/lsd`, `@cosmonaut/parser`, and `@cosmonaut/generator`).

While syntax-wise close to CSS (using `{ ... }`, `:`, `;`, and `@directives`), ASS defines its own independent semantics, dynamic cascade engine, and evaluation model. Native CSS serves strictly as a low-level target (emission target) generated by the ASS runtime.

# Syntax

**ASS** follows a very CSS-like syntax but there are some differents.

## custom properties

identifiers starting with `--` are custom props

```ass
// ASS
html {
  --color : #FF0000;
  --size  : 20px;
}

div {
  color : --color;
  width : --size;
}
```

```css
// CSS
html {
  --color : #FF0000;
  --size  : 20px;
}

div {
  color : var(--color);
  width : var(--size);
}
```

# at-rules

## @colors

the naming of keys follow strict rules which may seem a bit counter-intuitive at first glance but actually result in powerful flexibility of notating stuff for DX.

If the key is the name of an HTMLElement it applies to these kind of HTMLElments directly.

If the key is a selector it applies for the selector directly.

If the key is none of that it becomes an alias.

```css
@colors {
  soviet : red yellow;
  zombie : grey white;
}
```

```css
@colors {
  soviet : light-dark(lightred, darkred) yellow;
  zombie : light-dark(lightgrey, darkgrey) white;
}
```

## @fn

the name of the functions defines its lifetime:
- `--name` a real css-spec fn
- `$name` a temp fn
- `name` a "real" fn, still available at runtime

```css
@fn doSth ($arg1, $arg2) {

}
```

## Architecture Overview

```
[ ASS Source Code ]
       │
       ▼
[ ass.lsd ] ──► Cosmonaut Lexer & Parser (`parseASS`)
       │
       ▼
[ ASS AST ] ──► ASS Runtime Engine (`ASSEngine`)
       │        (Evaluates scopes, themes, traits & custom cascade)
       ▼
[ Evaluated AST ] ──► Cosmonaut Generator (`renderToCSS`)
       │
       ▼
[ Native CSS String ]
```

## Current Supported Language Features

### 1. Declarations
Property-value pairs ending with a semicolon.

```css
color: red;
margin: 10px 20px;
font-family: 'Inter', sans-serif;
```

### 2. Rules & Selectors
Standard block-scoped rules.

```css
.card {
  background: #fff;
  border-radius: 8px;
}
```

### 3. At-Rules
At-directives with optional parameters and statement blocks.

```css
@layer base;

@theme dark {
  bg-color: #000;
}

@scope (.card) {
  padding: 1rem;
}
```

Currently registered at-keywords in `ass.lsd`:
- `@scope`
- `@theme`
- `@layer`
- `@keyframes`
- `@media`
- `@aufbau`

## API Usage (Browser Runtime)

```javascript
import { compileASS, parseASS, ASSEngine, renderToCSS } from './index.js';

const source = `
  @scope (.container) {
    color: primary;
  }
`;

// 1. All-in-one compilation
const css = await compileASS( source );

// 2. Or step-by-step pipeline
const ast = parseASS( source );
const engine = new ASSEngine();
const evaluated = engine.evaluate( ast );
const outputCSS = renderToCSS( evaluated );
```

## the triangle

actually when writing sth. like this is a 3-way relationship

```css
body { line-height : 1.00; }
h6   { line-height : 1.50; }
p    { line-height : 1.25; }

// scheme
<selector> { <property> : <value> ; }
```

so why not switching the order?

```css
line-height { body : 1.00; }
line-height { h6   : 1.50; }
line-height { p    : 1.25; }

// scheme
<property> { <selector> : <value> ; }
```

and then group it like that?

```css
line-height {
  body : 1.00;
  h6   : 1.50;
  p    : 1.25;
}
```
